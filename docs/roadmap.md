# Планы и известные проблемы

Планы, связанные с приложением PictoLex (быстрая смена моделей, очередь загрузок, серверные задания, Gemma 4 и т. д.), ведутся в дорожной карте PictoLex; здесь — общие задачи шлюза.

## Известные проблемы

Найдены разбором кода 05.10.2026; проверены по коду, часть — экспериментом.

- **Приоритет очереди не действует**: у каждой модели своя очередь, и все её запросы имеют один приоритет.
- **`/metrics*` под ключом API**: при включённой авторизации Prometheus собирает метрики только с токеном (`authorization` в конфигурации сбора) — открывать ли `/metrics` без ключа, не решено.
- **Redis-кэш нельзя настроить**: у `CacheConfig` нет `redis_url`/`redis_prefix`, адрес всегда `redis://localhost:6379/0`, пакета `redis` нет в образе шлюза.
- **`defaults.stt` и `defaults.upscale` не задаются** через `server.yaml` (нет полей в `DefaultsConfig`), хотя роутеры их читают, а тесты подставляют.
- **Умолчания TTS из YAML** (`voice`, `speed`, `output_format`) не применяются: роутер всегда отправляет значения запроса (`default`, 1.0, `mp3`); `default` превращается в голос модели только у VoxCPM2 и Kokoro.
- **Meissonic игнорирует `size` запроса** (берёт ширину и высоту из YAML).
- **fp8** (`quantization: fp8`) требует `optimum-quanto`, которого нет ни в одном воркере.
- **Веса compel и LoRA** работают только в воркерах sdxl-base и sd35-medium (там есть `compel` и `peft`); у остальных синтаксис весов снимается.
- **Выгрузка на CPU**: `*_CPU_OFFLOAD=false` ничего не меняет, пока включена послойная выгрузка (`*_SEQUENTIAL_OFFLOAD`).
- **Grafana**: gauge-метрики обновляются только JSON-эндпоинтом `/metrics`, VRAM в шлюзе всегда 0.
- **Kokoro говорит только по-английски**: `KokoroTtsProvider` жёстко выбирает `lang_code="a"` и игнорирует `device` из YAML.
- **Поток ответа и `/reload`**: потоковый ответ идёт вне блокировки воркера и может пересечься с заменой провайдера; полный `/reload` держит в VRAM старую и новую модель.
- **Безопасность** при открытом шлюзе без авторизации: `loras` и `textual_inversions` скачивают любые репозитории Hugging Face, Caddy не закрывает `/cache` и `/v1/admin/*`, CORS `*` с `allow_credentials=True`.

## Возможности

- [ ] Несколько GPU: `CUDA_VISIBLE_DEVICES` на воркер и учёт VRAM по устройствам в `ProviderManager`.
- [ ] Апскейл по тайлам: сейчас вход ограничен 2048 px по стороне.
- [ ] Helm-чарт: Deployment шлюза и воркеров, ConfigMap для YAML, PVC для весов; основа — `gpu.worker_url_template`.
- [ ] Web-интерфейс: галерея, история промтов, живые метрики.

## Производительность

- [ ] Пакетный вывод эмбеддингов: сбор запросов в micro-batch по размеру или окну времени.
- [ ] Потоковая отдача картинок: промежуточные шаги через `callback_on_step_end` или PNG через `StreamingResponse` вместо base64 в JSON.
- [ ] Ключ кэша с применёнными умолчаниями модели: сейчас смена `default_params` в YAML не сбрасывает кэш тех же `seed + prompt`.

## Несколько экземпляров шлюза

- [ ] Общий лимит запросов через Redis: сейчас скользящее окно в памяти процесса, и за балансировщиком лимит умножается на число шлюзов.
- [ ] Рассылка перезагрузки конфигов между экземплярами (Redis pub/sub или NATS).

## Наблюдаемость

- [ ] OpenTelemetry: спаны FastAPI и httpx с экспортом OTLP (`X-Request-ID` уже передаётся воркерам).
- [ ] Журнал в JSON для всех логгеров, а не только access log.
- [ ] Метрики здоровья воркеров и пула соединений httpx.
